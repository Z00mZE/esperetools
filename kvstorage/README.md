# kvstorage

Key-value хранилище во flash ESP32 для TinyGo. Записи сохраняются при перезапуске
и отключении питания. Компонент не зависит от ESP-IDF NVS или сторонних библиотек.

## Использование

```go
import "github.com/Z00mZE/esperetools/kvstorage"

storage, err := kvstorage.Open()
if err != nil {
	return err
}

// После успешного SetString значение уже находится во flash.
if err := storage.SetString("ssid", "Home Wi-Fi"); err != nil {
	return err
}

// После выключения и включения платы снова вызовите Open и GetString.
ssid, found, err := storage.GetString("ssid")
```

Фрагмент предназначен для функции, возвращающей `error`. Полная программа:
[`examples/basic/main.go`](examples/basic/main.go). Она записывает значение только
при первом запуске и читает его при последующих включениях.

```sh
# Проверка сборки без прошивки платы
GOFLAGS=-buildvcs=false tinygo build -target=esp32s3-generic -serial=usb -o kvstorage.elf ./kvstorage/examples/basic

# Прошивка примера и запуск монитора
GOFLAGS=-buildvcs=false tinygo flash -monitor -target=esp32s3-generic -serial=usb -port=COM6 ./kvstorage/examples/basic
```

После первого сообщения `Saved name` завершите монитор через Ctrl+C, отключите
питание платы и подключите её снова. **Повторно прошивать не нужно.** Откройте
монитор:

```sh
tinygo monitor -target=esp32s3-generic -serial=usb -port=COM6
```

Сообщение `Loaded from flash: ESP32` означает, что программа прочитала сохранённое
значение. Если сообщение было выведено до подключения монитора, нажмите Reset при
открытом мониторе. Замените `COM6` на порт своей платы. Синтаксис `GOFLAGS=...`
в командах выше предназначен для Bash/UCRT64.

## API

| Метод | Назначение |
| --- | --- |
| `Open() (*Store, error)` | Открыть стандартную область flash на ESP32-C3/S3 |
| `Set(key string, value []byte) error` | Сохранить байтовое значение |
| `Get(key string) ([]byte, bool, error)` | Прочитать копию значения и признак наличия |
| `SetString(key, value string) error` | Сохранить строку |
| `GetString(key string) (string, bool, error)` | Прочитать строку и признак наличия |
| `Delete(key string) error` | Сохранить удаление ключа |
| `Has(key string) (bool, error)` | Проверить наличие ключа |
| `Keys() ([]string, error)` | Получить ключи по алфавиту |
| `Clear() error` | Сохранить удаление всех ключей |

Ключи чувствительны к регистру и содержат от 1 до 255 байт; Unicode допустим.
Значения — произвольные байты, в том числе пустой массив. Для отсутствующего ключа
геттер возвращает нулевое значение, `found=false`, `err=nil`. Для существующего
ключа с пустым значением возвращается `found=true`. `error` сообщает о настоящей
ошибке. `Delete` отсутствующего ключа возвращает `ErrNotFound`.
`GetString` интерпретирует сохранённые байты как строку;
отдельные типы значений в хранилище не задаются.

Числа и структуры можно кодировать через `encoding/binary` или `encoding/json`
в вызывающем коде, затем передавать в `Set`.

`Set`, `Delete` и `Clear` сохраняют результат сразу: отдельного `Commit` или
`Close` нет. Повторный `Set` с тем же значением не записывает flash. Методы одного
`Store` можно вызывать из нескольких goroutine. Для одной области flash создавайте
один `Store`; из обработчиков прерываний методы вызывать нельзя.

## Где находятся данные

Готовый адаптер `Open` использует последние **8 КиБ области `machine.Flash`**,
а не произвольный адрес сразу после прошивки. В установленных generic-целях
TinyGo 0.44.0 для ESP32-C3/S3 конец этой области соответствует границе первых
4 МиБ flash. Например, на ESP32-S3 с 16 МиБ физической памяти стандартная область
хранилища всё равно находится в диапазоне `0x3FE000..0x400000`.

Эти 8 КиБ должны принадлежать только `kvstorage`: не размещайте там файловую
систему или другие данные. Если в области ещё нет разметки `kvstorage`, она
открывается как пустое хранилище, даже если байты не равны `0xFF`: прошивка платы
не обязана стирать всю flash. Первый `Set` автоматически стирает нужный банк,
создаёт разметку и сохраняет значение. Ручное форматирование не требуется.
Повторный `Open` читает сохранённую разметку без очистки. Повторный `Set` по тому
же ключу заменяет значение, а `Delete` сохраняет удаление.

Два банка по 4 КиБ дают примерно **4 КиБ полезных данных**, включая ключи
и служебные поля; при переполнении возвращается `ErrFull`, прежние данные остаются.

Для другой области или большего объёма:

```go
// offset — относительно переданного flash, size — весь размер обоих банков.
storage, err := kvstorage.New(flash, offset, size)
```

`flash` реализует интерфейс [`Flash`](kvstorage.go); на поддерживаемых платах
подходит `machine.Flash`. Начало области и каждый из двух равных банков должны
быть выровнены по блокам стирания. Каждый банк занимает минимум 4096 байт.

Само хранилище работает без платформенных зависимостей. Готовый `Open` доступен
для ESP32-C3/S3, где установленный TinyGo предоставляет `machine.Flash`. Для
классического ESP32 потребуется flash-драйвер, реализующий `Flash`.

Отключение питания не стирает flash. Полное стирание чипа, запись другой прошивки
поверх области и смена её физического адреса могут удалить данные. Для обновляемых
промышленных прошивок закрепите область в linker/target-конфигурации и ограничьте
размер кода так, чтобы он не мог её перекрыть. При смене target проверьте адреса.

## Как сохраняются данные

В каждом банке находится полный снимок ключей и значений. При изменении:

1. Стирается неактивный банк; текущая копия остаётся нетронутой.
2. Записываются заголовок, номер поколения, данные и CRC32.
3. Последним записывается маркер завершённой записи.
4. Новый банк читается обратно и проверяется. Только после этого операция
   возвращает успех и новая копия становится текущей.

При следующем `Open` выбирается последний корректно завершённый снимок. Если
питание пропало во время записи или стирания неактивного банка, предыдущий снимок
остаётся доступен. Незавершённая запись не смешивается со старой.

После ошибки изменения flash handle возвращает `ErrNeedsReopen`: откройте
хранилище заново и прочитайте фактический результат. Операция могла успеть
сохраниться, даже если проверка чтением закончилась ошибкой.

Отсутствие разметки — штатный первый запуск. `ErrCorrupt` возвращается, когда
есть признаки ранее созданных снимков `kvstorage`, но ни одна копия не читается.
Автоматического стирания при такой ошибке нет. При необходимости **явно удалить все данные**
стандартной области можно вызвать `FormatFlash()`, а произвольной области —
`Format(flash, offset, size)`. Не вызывайте форматирование при каждом старте.

Компонент рассчитан на настройки и небольшое состояние. Каждое изменение
перезаписывает снимок и стирает один банк, поэтому это не хранилище для
непрерывного потока измерений. Данные не шифруются.

## Проверки

```sh
go test ./kvstorage
go vet ./kvstorage
```

Тесты проверяют повторное открытие после выключения, замену и удаление значений,
границы flash, переполнение и сбои на каждом этапе записи. Моделируются в том
числе частичная запись заголовка/данных/маркера и частичное стирание сектора.
Проверку реального отключения питания на плате нужно выполнить отдельно.
